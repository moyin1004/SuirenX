# SuirenX 下一阶段产品规划

日期：2026-09-15。状态：已授权实施，阶段 A 部分完成；详见[执行检查点](roadmap-execution.md)。B/C 依赖 OpenDesign 恢复，D 保持候选。

## 1. 目标与判断

让用户能持续、轻松地记录自己的物品，准确找到记录，在到期前采取行动，并相信数据能够保存和恢复。

当前已有资产完整生命周期、标签与名称搜索、用品保质期、版本化 JSON 备份恢复、账号与可选后台同步。下一阶段围绕这些能力形成日常使用闭环。暂缓新工具品类、独立趋势页、Web 和 iOS 扩张。

假设：近期仍以个人 Android 使用为主；快速录入、查找和避免遗漏到期，比增加平台数量更有价值。以下优先级是基于当前实现与使用路径的判断，未采集用户行为数据，不虚构 RICE 分数或收益百分比。

## 2. 审查范围与证据边界

- 阅读当前工作树的总览、资产列表/ViewModel、资产表单、用品列表/表单/ViewModel、设置页、用品模型及 TODO。

- 当前账号/地址改动尚在工作树中；以 2026-09-15 的规则为准：唯一登录账号与地址独立，切换地址保留账号，凭证不能跨地址发送。旧记录中“切换地址清凭证”已被替代。
- 本文是产品规划，不代表已执行构建、设备测试、部署或任何功能修改。

## 3. 优先处理的逻辑与 UI

| 优先级 | 当前证据 / 问题 | 建议变化 | 验收结果 |
| --- | --- | --- | --- |
| P0 | `OverviewScreen.kt` 的待同步/冲突提示调用 `onAssets`，资产页已没有对应处理入口 | 提示直达设置中的同步状态或冲突列表；日常列表保持业务内容 | 从提示一次进入能处理问题的页面，返回保留原位置 |
| P0 | `AssetsViewModel` 报“无法读取本机数据”，`AssetsScreen.ErrorState` 却显示“同步没有完成 / 重新同步” | 区分本机读取错误与后台同步错误；读取失败按钮明确为重试读取 | 断网仍可读写；本机错误不引导用户处理服务器 |
| P0 | TODO 仍有真实双设备 HTTP、后台调度、旧库升级验收待办；用品空位置服务端修复部署状态待确认 | 建立一轮发布验收，先核对手机所连实例是否包含修复；设备不足时明确保留未验收项 | 两端新增/修改/删除、并发冲突、断网重试、重启后续传均保留正确数据；旧库升级无丢失；空位置可同步 |
| P1 | 总览“总资产”实际为未归档资产购入金额之和，包含退役资产；日均仅统计服役中资产 | 明确“购入总额”与统计口径；保持领域计算规则，避免被理解为当前估值或净资产 | 同一组数据在总览、资产页、筛选和归档间口径一致且可解释 |
| P1 | 资产刷新每次先置 loading，列表以 loading 分支替代已有内容 | 首次读取显示加载态，后续刷新保留已有内容与滚动位置；失败保留旧内容并标明状态 | 保存返回、后台数据变动不让已有列表整体消失 |
| P1 | 资产表单返回直接关闭；用品编辑器关闭直接清空状态；日期为文本输入 | 增加有修改时的离开保护、日期选择与手输兼容、字段附近校验；定义进程重建后的草稿恢复 | 无修改直接返回；有修改可继续编辑或放弃；失败保留输入；保存只产生一条记录 |
| P1 | 用品编辑含多个字段但放在 AlertDialog；详情底部并列编辑/用完/丢弃/归档/关闭等动作 | 新增/编辑改分组全屏表单；详情清晰区分主要动作、归档与删除；显示实际到期日及其计算依据 | 键盘打开与大字体下可完成录入，用户理解包装期限与开封期限取较早者 |
| P1 | 用品标题“下一次补充，提前知道”，现有数据只有期限，没有库存或消耗速率；状态卡以 remoteMode 显示“服务端” | 文案聚焦到期管理；本地数据来源和同步状态分开表达 | 页面不暗示补货预测，也不暗示启用同步后数据源变成服务器 |
| P1 | 资产已支持名称/标签搜索和生命周期筛选，但没有用户排序；用品缺少名称搜索入口 | 在既有搜索上补排序、标签组合筛选；用品加名称/位置搜索；明确筛选条件与清空入口 | 搜索与筛选可组合，无结果态保留条件且可一键清空，返回列表保留条件 |
| P2 / 待实测 | 资产为固定两列，部分辅助字为 9–11sp；用品详情动作横向拥挤 | 核查窄屏、大字体、深色和 TalkBack；必要时自适应单列、动作换行与提高关键文字可读性 | 200% 字体与窄屏不丢信息或动作，关键状态有文字语义，末项不被底栏遮挡 |

额外回归：跨午夜、后台返回后的持有天数/保修/临期状态应更新。现有模型依赖“今天”，本轮尚未验证完整跨日触发路径，不能把历史领域测试当成当前 UI 验收。

## 4. 按用户结果安排交付

### 阶段 A：数据可靠、遇到问题有入口

- 内容：P0 三项；统计口径；已确认的账号/服务器流程回归；备份恢复与同步相互作用验收。
- 成果：本地保存不依赖网络，失败有准确解释，冲突有可达入口，恢复有退路。
- 放行条件：上述关键路径全部通过；未获得双设备或部署环境时持续注明缺口，不宣称同步全量验收完成。可继续独立的本地体验工作。

### 阶段 B：更快录入、更快找到

- 内容：资产/用品表单、日期选择、未保存保护、稳定刷新；资产排序和组合筛选、用品搜索。
- 首批排序：购买日期、购入金额、日均成本；定义升降序、相同值稳定排序与记忆规则。标签先复用现有数据，不把图标种类直接当成新的业务分类体系。
- 成果：录入少出错，几十到上百条记录时仍容易定位。
- 验收：选取 5 个固定查找任务，均在 3 次操作内完成（文字输入算一次）；用同一组物品比较改动前后录入耗时与修正次数，先记录基线再定提升目标。补测筛选/排序口径、搜索无结果、保存失败、返回和重建。

### 阶段 C：不打开 App 也能得到有用提醒

- **优先新增功能：到期提醒，先用品临期，再保修到期。** 复用现有到期日与保修截止日，避免引入新工具数据孤岛。
- 最小范围：用户主动开启；提醒时间与提前天数；每日合并摘要；点击进入对应待处理记录；无通知权限时仍有应用内提醒。
- 规则先明确：到期当天/过期后的提醒频率；已用完、已丢弃、已归档或已删除项目不提醒；编辑日期和同步更新后旧提醒失效；同一天重试不重复轰炸；切换时区、重启和系统限制下如何表现。
- 保修提醒独立于用品阈值：不将“保修过期”等同于资产不可用。具体阈值以使用反馈决定。
- 首页随后增加可点击的待处理项目摘要；每条直接到详情，全部处理后自然收起。先保持四个主 Tab，评估使用后再决定导航调整。
- 验收：真实设备验证开启/拒绝权限、应用退出、重启、跨日、日期修改、处理完成后不再提醒；具体 Android 调度与权限方案在实施前核对官方文档，不能承诺精确到分钟必达。

### 阶段 D：用真实使用反馈决定扩展

| 候选功能 | 价值 | 建议条件 |
| --- | --- | --- |
| 复制记录 / 再买一件 | 重复用品免重填 | 优先轻量实现；复制名称/分类/位置等，日期重新确认，新 ID，不复制旧处理状态与同步元数据 |
| CSV 导入导出 | 批量迁入现有物品，方便自主使用数据 | 用户确实有表格再做；先模板和预览、逐行错误、重复策略、事务及备份；JSON 仍用于完整恢复 |
| 标签与位置管理、批量归档 | 大量记录下减少重复操作 | 根据阶段 B 的使用量与反馈推进；批量删除另行设计 |
| 出售回收金额、维修记录 | 更完整的持有成本 | 先确认是否真有记录需求，并定义与现有日均成本的关系；首轮不增加录入负担 |

暂缓：库存预测、条码/OCR/AI 自动录入、订阅管理等新工具、独立趋势图、Web/iOS、数据库替换和 C++ 重写。当前缺少足够需求或性能证据支撑优先投入。

## 5. 下一批可执行任务

1. 修订现有 OpenDesign：同步提示跳转与错误态、统计文案、用品文案；补齐加载/空态/无搜索结果。
2. 实现阶段 A 的入口与状态修正，并开展真实同步验收。
3. 更新 OpenDesign 的表单与列表交互，随后落地阶段 B；设计不可用时记录差异并继续无依赖任务。
4. 编写到期提醒小规格：时间、权限、去重、点击目标、处理后撤销；再更新设计并实施。

规划用阶段表达依赖，不在缺少容量与真机条件时承诺具体日期。UI 依赖变更继续遵循先更新 OpenDesign、再实现 Android。

工程支持：发布前补齐 CI 最小门禁、版本/签名与分发说明；测试随上述风险路径补充。KSP 等构建迁移按工具链必要性安排，避免占用全部产品迭代。
