# 到期提醒实施规格

2026-09-15：按已授权路线图细化。规则待 OpenDesign 表达后实施，当前未增加通知能力。
2026-09-22：确认用品当前仅做期限管理，采用本文件默认提醒方案，不引入库存、消耗或补货预测。

## 目标与范围

用户主动开启后，每天收到一条到期摘要，点击可处理对应物品。所有计算读取本地 Room，不依赖账号或服务器可用。首批用品，随后保修；不增加库存预测。

## 产品规则

- 默认关闭。用户开启时解释用途并请求必要通知权限；拒绝权限后应用内提醒继续有效，设置显示实际权限状态并提供恢复入口。
- 默认每日 09:00（设备本地时间），允许修改。该时间为期望发送时间，系统可能延后，不承诺精确闹钟。
- 用品提前天数复用现有临期设置。已过期、今日到期、临期且在用的未归档项目纳入摘要；已处理、归档、删除项目排除。
- 每天至多主动提醒一次，过期项目未处理时进入下一天摘要；同一天任务重试或同步更新不重复发声。
- 编辑日期、处理、归档、删除或同步更新后重新读取数据，更新现有通知内容；无待处理项目则撤销通知。当天已提醒但新增临期项目，留待下一天主动提醒。
- 保修提醒单独配置，建议初值提前 30 天；仅未归档且服役中、有保修截止日的资产。已过保修期不持续每天催促，也不改变服役状态。
- 修改系统日期/时区、重启或调整提醒时间后重算下一次调度；不补发多天历史通知。
- 点击摘要进入对应待处理列表；点击单条入口时重新按 ID 读取，记录不存在或已处理则回到列表并说明状态。

## 实现边界

- 通知偏好、当日本地去重状态不加入资产/用品同步或 JSON 业务备份；新安装默认关闭，恢复业务数据不擅自开启通知。
- Worker 执行时重读偏好、权限和 Room；唯一调度与发送互斥，避免并行任务重复通知。
- 使用固定通知 ID 使同日重试替换已有通知；平台发送与数据库提交不能构成一个事务，应设计进程中断后的补偿，不能只靠内存布尔值去重。
- 系统调度与后台返回触发同一规则，界面显示与通知共享同一日期/临期口径。
- 实施前核对 Android 官方通知权限、渠道和 WorkManager 文档；遵循当前目标 SDK 要求。这里尚未确定最终调度实现。

## 验收

1. 关闭、拒绝权限、允许权限、系统关闭通知后状态准确。
2. 今日到期/昨天过期/临期边界/开封期限均与界面一致。
3. 修改日期、用完、丢弃、归档、删除后通知更新或撤销。
4. 同一天重复任务、进程重建、离线与同步更新不重复发声。
5. 重启、跨日、时区切换、修改提醒时间不补发旧摘要。
6. 点击进入正确记录；删除或处理后旧通知入口能恢复到可用页面。
7. 真机检查系统延迟行为；测试调度成功不等同于全天后台可靠送达验收。
