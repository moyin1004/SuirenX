# 数据存储与同步

2026-09-07。本文合并原本地模式、M5 同步设计、阶段计划和实施检查点中的数据规则。下面明确区分当前代码与待实施方案。

## 当前实现

资产和用品统一使用本地 Room 业务表。业务写入/删除与同步 journal 同事务提交；服务器不再提供资产 CRUD。LocalFirstSyncRepository 在 HTTP 前持久化固定批次，最多 100 条，幂等键随批次保存。响应确认、业务应用和游标推进同事务提交；网络请求不占用 Room 事务。通过本地 revision 判断在途新编辑，保留新值并使用已确认服务器版本继续发送。

显式同步单实例执行，重复点击不积累网络任务，60 秒超时后保留批次。冲突保留到记录层，其他记录继续同步。每次修改后由 WorkManager 触发；定时选项为约 15 分钟/1 小时/6 小时/每天。修改后模式另有约 15 分钟的后台补偿任务，处理提交后进程退出等情况。

Room 升级为 v3，新增 journal 与 session 表，不改写已有业务行。第一次同步前自动备份，事务绑定服务器/账号并整理该账号旧缓存和未确认操作；原缓存库保留。发生本机/旧缓存同 ID 差异时保留本机并另存旧修改，避免静默覆盖。更换账号/服务器后不再阻止同步；用户登录并预览确认开启后，为新目标重新建立同步基线。

资产和用品删除时移除可见行，journal 保留完整删除 payload。归档仍可恢复，删除独立确认。旧接口客户端需升级，旧服务端开发库按新的 001 校验不匹配时需先备份再显式重建。

## 架构约定

资产和用品始终以设备 Room 为唯一事实来源；无服务器也可新增、编辑、删除、归档、查看和计算。服务端仅保留认证、设备同步、健康检查，不再提供面向业务的 CRUD 接口。业务 ViewModel 只调用本地仓储；独立同步协调器负责上传变更、拉取增量并提交本地事务。

每次本地修改与 outbox 一起提交。冻结批次使用稳定幂等键，网络调用不能放进 Room 事务或阻塞主线程。同步过程单实例运行；重复点击不排成长队。返回时按本地修订号比较，防止旧响应覆盖同步期间的新编辑。服务器版本用于并发检测，设备时间只用于展示。

首次同步时记录服务器与账号作为同步目标并自动备份，可在设置中预览本机记录数量；同名记录不作为重复判断依据，仅相同 UUID 参与版本比较。允许更换账号/服务器，保存地址或登录本身不上传；用户预览确认开启同步后，将本机数据同步到当前目标。切换目标前自动备份业务数据及旧同步快照，事务重置版本、游标和固定批次；保留本机记录和 tombstone，同 ID 差异仍人工处理。退出账号停止网络同步，保留本机可用数据。旧本地库和旧远程缓存迁移要有幂等标记与失败回滚，不能通过清库规避。

## 同步触发方案

设置提供“每次修改后同步”和“定时同步”，始终保留“立即同步”。每次修改先保存成功，然后后台合并短时间内多次触发。定时建议 15 分钟、1 小时、6 小时、每天；Android 后台调度受省电和网络限制，界面显示“约每…”而非承诺精确时刻。断网保留队列，联网后退避重试；认证过期单独提示重新登录。同步错误不将本地保存显示为失败。

设置状态：未开启、已同步、等待网络、同步中、需登录、失败可重试、若干记录待处理。显示上次成功时间、待发送数量和冲突数量。取消后台工作仅停止这次网络请求，不清理持久化批次。设置页展示不定进度并可停止当前请求；持久化批次保留供下次重试。

## 冲突方案：已确认保守策略

用户已确认首版采用整条版本冲突：保留本机、保留另一端或另存一份，不自动做字段合并。

| 情况 | 建议行为 |
| --- | --- |
| 一端修改，另一端未修改 | 自动同步 |
| 双方内容相同但基线已过期 | 首版仍展示版本冲突；自动确认一致留作后续优化 |
| 双方改同一记录 | 保留双方快照与共同基线，仅暂停此条；其他记录继续 |
| 用户选择保留本机 | 基于最新远端版本重新提交；若又有变化再次检测，不强制覆盖 |
| 用户选择保留另一端 | 本地事务应用远端版本；仅移除对应已确认的本地操作 |
| 用户选择两份都保留 | 保留原记录，另一份用新 UUID 创建并标注副本 |
| 一端删除、另一端修改 | 明确展示删除与修改冲突，可保留删除或将修改版另存；不静默丢弃修改 |
| 双方删除 | 自动达成一致 |
| 删除已同步但旧设备离线 | 服务端保留 tombstone；没有设备确认/全量重同步协议前不自动回收 |
| 没有权限读取远端快照 | 仅提示归属冲突，不显示跨账号内容 |

不推荐直接“最后写入覆盖”：设备时间可能不准，且会静默覆盖金额、日期或备注。三方自动合并需要持久化共同基线，并把购买/退役日期、状态等关联字段成组校验；标签、备注也需要明确合并规则。因此建议作为后续增强，而非第一版默认。

冲突页以资产/用品名称为标题，显示“本机”和“另一端”的字段差异、修改时间、删除状态。先展示差异再给操作按钮，选择会删除任一版本时二次确认。退出冲突页不影响继续使用应用。

## 设置页设计 Brief

沿用现有资产页的燧人顶部栏、留白、浅色细边框卡、圆角与黑色主操作，适配深色主题。删除“数据来源：本地/服务端”的选择，把“数据始终存本机”作为清晰说明。

入口分组：同步（连接状态、立即同步、同步方式、冲突处理、账号与服务器）；备份与恢复（本机数据导出、恢复预览、安全备份）；外观；用品临期提醒；关于。未开启同步时只显示说明与开启入口；连接与账号表单放入二级页，不堆在设置首页。需要覆盖配置、登录、开启预览、两种触发方式、离线/失败、冲突处理、暂停同步与更换账号。

### 2026-09-10 账号与服务器流程

- 按用户决定取消旧目标绑定阻拦。旧 journal（含双方冲突快照）和 session 随 `pre-remote-import` 自动备份保存为 `syncRecovery`，不含凭证；恢复业务备份不会复用旧同步元数据。新目标使用新的幂等键、零版本和零游标，失败后仍复用新目标的固定批次。
- 注册成功自动登录并返回账号与服务器页；登录成功同样返回，清空密码及确认密码。输入规则与服务端一致：非空账号最多 100 个 UTF-8 字节，注册密码 8–72 字节，确认密码一致。字段下显示不可提交原因，并支持显示/隐藏密码。
- 登录/注册切换清空密码和旧错误；请求中禁止重复提交或切换/删除服务器。过期连接的迟到登录响应不得保存为新连接的凭证。显示当前账号、服务器和切换账号入口。
- 离线退出仍清除本机凭证，服务端注销请求最多等待 3 秒；离线时无法保证旧服务端令牌已撤销，应用不再使用该令牌。保存地址不依赖服务器在线；重复地址更新名称并选中。
- 不虚构未实现的找回密码、修改密码或注销账号能力。本轮不改变服务端账号间的数据隔离。

### 2026-09-10 服务器详情、连接测试与 HTTP 400

服务器管理按“列表 → 单个服务器详情 → 该服务器账号”组织；添加与编辑分离。新增不切换当前同步目标，编辑更新原条目并拒绝重复地址；仅改名称保留同步和凭证，改 URL 清除该服务器旧凭证，若为当前目标则暂停同步。多个服务器各自保存登录状态，旧单凭证偏好原子迁移。登录/退出非当前服务器不改变当前目标。

连接测试读取表单输入，独立请求 `/healthz` 并要求 `status=ok`；不携带认证、不跟随重定向、不保存配置、不登录、不启用同步。输入变更使上次结果失效。成功仅说明健康接口可达，不保证认证和同步兼容。

排查手机失败批次发现用品位置为空，而服务端此前错误要求非空。已将服务端校验与 App 的可选位置规则对齐，并对资产备注/标签采用字符长度限制。400 在客户端以同步状态卡中的中文说明展示，附带可用的服务端原因；不丢弃或擅自改写固定重试批次。

验证：独立模拟器覆盖凭证迁移、跨服务器账号隔离、地址修改/重名拒绝；真实本机服务健康测试成功、编辑名称不新增条目；人工空位置用品通过真实 HTTP 同步返回 200。未重放手机原始数据，远端实例仍需部署服务端修复。
