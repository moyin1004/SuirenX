# M5 身份与同步设计

公共契约位于 `api/proto/suirenx/m5/v1/m5.proto`；脚本会校验该 IDL 的 descriptor，当前 Hertz 资产路由之外的 M5 路由使用同一 HTTP JSON 约定，由内部 transport handler 显式绑定，避免把认证与同步请求混入资产生命周期路由。资产与用品各自使用游标，避免两个独立事件表共享单一游标造成漏变更。

M5 的实现前置条件固定为“账号主体 + 服务端授权隔离”，不把本地整数 ID 当作跨设备身份，也不在没有冲突提示时采用最后写入覆盖。

## 身份与数据归属

- 账号由服务端账号服务建立，密码使用 bcrypt 保存，API 只接受经过验证的 bearer token。
- 每条资产和用品使用随机 UUID 字符串作为跨设备 ID；所有查询和变更都带授权主体条件。
- 服务端记录 `owner_id`，越权读取、编辑、归档和删除统一返回 404，避免泄漏其他账号是否存在记录。
- 退出登录只清理该账号的本地授权令牌和通知任务；本地库记录保留，重新登录后不自动上传。

## 版本、删除与幂等

每条可同步记录携带单调递增的 `version`、`updated_at` 和可选 `deleted_at`。删除先写 tombstone，保留到所有设备确认后再由服务端回收。写请求携带 `idempotency_key`，服务端按 `(owner_id, idempotency_key)` 保存结果，重试返回同一结果，不重复创建或变更。

同步使用按游标的增量接口：客户端提交本地变更批次，服务端返回接受结果、冲突和从游标之后的远程变更。批次和单条变更都可重试；服务端不依赖客户端时间戳解决顺序。当前服务端已实现资产和用品两套游标、批量上限、幂等响应缓存、owner 隔离、版本冲突快照和 tombstone；普通资产 CRUD 也会产生同步事件。

## 冲突规则

客户端编辑携带 `base_version`。服务端版本不同则返回冲突快照，不静默覆盖。首版冲突 UI 展示本地/服务器快照摘要，由用户选择保留服务器或保留本机；保留本机时以服务器最新版本重新定基线并提交，保留服务器时删除对应待同步操作。资产和用品冲突记录均持久化在独立 Room 表，不能通过删除重建规避。

## 本地迁入远程与离线

本地迁入远程是设置中的显式流程：生成资产和用品预览，按稳定 ID 与名称/金额/购买日期或名称/包装到期日规则去重，先保存本地安全备份，用户确认后逐条以稳定 UUID 和幂等 key 上传；任一条失败会列出名称，重试会跳过已存在记录，切换模式不触发迁入。

远程模式的离线缓存按“服务器 origin + 账号”隔离；写操作先写 durable outbox，联网后按版本和幂等 key 重试，服务器连接失败不能自动转成本地模式。用品提醒使用同一账号的最近成功缓存，并显示来源与 `lastSyncedAt`；账号切换/退出不会读取旧主体的缓存或待同步操作。
