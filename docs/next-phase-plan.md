# 下一阶段实施计划

2026-09-06。范围：资产信息扩展、体验适配、数据保障、可选本地模式、保质期工具；删除心愿和趋势页。本文件是实施方案，尚未代表功能已落地。字段与提醒默认值为建议，可随实现前的产品细化调整。

## 交付顺序

按 M1 本地模式与备份 → M2 资产字段 → M3 工具与保质期 → M4 全面适配验收 → M5 身份与同步推进。M4 的主题、布局和语义要求从新增界面开始执行。M1–M4 构成下一版可用交付，M5 是数据保障的后续完整阶段，不以首版免登录替代同步需求。

## M1：无需服务器即可使用

首次启动展示「本地使用」和「连接服务器」。已有远程配置继续使用原配置；设置中展示当前模式与切换入口。仅远程模式要求填写服务器地址。

本地模式由 Room 持久化资产，是该模式唯一事实来源，离线可完成全部资产操作。远程模式继续以服务器为事实来源，断网保留明确错误与重试行为。本地库与各远程地址的数据互不合并；切换不删除、不上传，也不自动复制。必须隔离旧模式的在途请求、详情、列表和变更事件，避免旧响应覆盖新模式状态；有未保存表单时提示保存或放弃。

通过现有领域仓储接口选择数据实现；Room Entity、DAO 和 Retrofit DTO 留在数据层。日期和成本计算放在纯 Kotlin 领域逻辑中，以同一组输入输出验证与 Go 服务一致。模式选择持久化，进程重启和跨日恢复均正确。引入 Room 前先完成这些规则的设计记录与数据库迁移方案，不启用破坏性迁移。

首版本地无需账号，提供有格式版本的完整备份文件，保留 ID、状态、归档、标签和时间信息。恢复采用明确的整库替换流程：先校验格式与关联关系、展示记录数和覆盖范围、备份当前数据，再由用户确认后事务恢复；失败不留下部分记录。旧备份新增字段使用默认值，未知未来版本拒绝导入。备份不含凭据，默认不改变远程地址和当前模式；恢复目标明确为本地库。远程数据继续采用服务端数据库备份，不能把本地导出称为远程备份。

验收：飞行模式首次启动无需地址，完成新增→编辑→退役→恢复→归档→恢复；杀进程数据仍在；本地/远程切换互不污染；完整备份往返一致，损坏文件和恢复失败均保持原数据。

## M2：资产资料更完整

金额字段已存在，继续使用整数分。本轮增加可选购买渠道、保修截止日、备注与标签；保修以截止日作为唯一存储值，避免同时保存时长和日期导致冲突。建议渠道上限 100 字、备注 2000 字、最多 20 个标签且每个 30 字，标签去首尾空白、去重；日期有效性与字段清空规则在接口设计时固定。

新字段覆盖本地、远程、新建、编辑、详情、备份与恢复。旧客户端未传的新字段应保留原值，显式清空必须可表达；在修改 Proto 前确定字段存在性方案并加入 HTTP 契约测试。服务端只追加下一编号迁移，本地迁移保留所有已有资产。归档继续只读。

验收：新旧记录均可打开；编辑旧字段不清空新增资料；标签空数组和清空操作可往返；购买金额和现有总览计算不受影响；本地与远程操作结果一致。

## M3：工具页与日用品保质期

导航调整为「资产 / 工具 / 设置」。工具页以「保质期管理」作为首个工具入口，为以后添加工具留位置。删除心愿和趋势占位页及路由。新增按钮按当前页面创建资产或用品，设置页不显示新增按钮；工具入口页通过明确的保质期卡片进入用品管理。

用品独立于资产建模，不进入资产总额、日均成本或服役统计。建议新增 `feature/tools` 入口模块和 `feature/expiry` 功能模块，领域模型和仓储接口仍留在 core:model/domain。本轮用品保存在本机，在本地/远程资产模式下均可使用并明确显示存储位置；切换资产服务器不会切换用品库。后续远程用品通过独立 Proto 契约扩展。

每件/每批用品独立记录：名称、分类、包装到期日；可选开封日、开封后有效天数、存放位置、备注。相同名称不同到期日分别建记录。首版直接输入包装到期日，不增加条码查询或 OCR 依赖。开封日与有效天数成对填写，开封日不得在未来，有效天数为正整数。

建议日期规则：实际到期日取包装到期日与「开封日 + 有效天数 − 1」的较早值，有效天数包含开封当天。当天等于到期日显示「今日到期」，次日起显示「已过期 N 天」；临期默认 7 天，可在设置中修改。所有计算按设备当前本地日期执行，跨日、恢复前台、修改日期/时区后重算，不依赖写入时缓存的过期标志。

用品状态为在用、用完、丢弃，归档独立且可恢复。已用完、丢弃或归档不参与提醒；恢复在用后重新计算。过期本身是日期推导结果，不自动删除、归档或更改状态。

强提示采用多处持续可见的方式：应用主界面显示「有 N 件用品已过期」醒目摘要，点击直达过期清单；工具 Tab 显示数量标记；清单按已过期、今日到期、临期、正常展示，详情带图标、文字和状态色。仅打开或阅读不会清除提醒，用户可标记用完、丢弃或归档；避免每次切页反复弹阻断弹窗。

系统通知作为可选增强：解释用途后请求权限，默认每日汇总一次已过期/今日到期/临期用品；按用品和提醒日期去重，编辑、处理、恢复备份后重新协调待提醒任务。用户拒绝通知时应用内强提示仍完整可用。调度实现前核实目标 Android 版本的后台和通知限制，不承诺精确到点送达。

验收：覆盖当天、昨日、闰日、跨年、开封期限早于包装期限、跨日与时区变更；过期状态文字可被 TalkBack 读出；拒绝通知仍有醒目入口；处理后计数与通知同步消失，恢复后正确重新出现；用品备份恢复完整。

## M4：适配与无障碍验收

设置支持跟随系统、浅色、深色。为现有分类色及告警定义适配深色的主题色，不依靠颜色单独区分状态。布局不以固定卡高限制正文，金额、标签、按钮允许合理换行；适配 200% 字体、横屏、平板和分屏，表单键盘弹出后仍可操作。

验收覆盖至少浅/深主题、默认/200% 字体、手机竖/横屏和平板；点击目标至少 48dp；普通文本对比度目标 4.5:1；TalkBack 能依序识别导航、输入标签、错误、过期摘要及处理动作，装饰图标不重复播报。保留滚动位置，避免悬浮栏、系统栏与键盘遮挡内容。

## M5：身份与跨设备数据保障

先确定账号体系、服务端数据归属与授权隔离，再设计稳定跨设备 ID、记录版本、删除标记、增量同步、幂等重试和冲突展示。禁止依靠本地整数 ID 跨库直接合并或无提示地用最后写入覆盖冲突。

本地迁入远程是独立显式操作，需预览范围、去重规则、备份与失败恢复，切换模式不触发迁移。远程离线能力须明确本地缓存作为何种事实来源、待同步操作队列和冲突策略后再实施；同时定义用品提醒的缓存时效、账号切换与退出后的通知清理。

验收包含两台设备并发编辑、离线后重连、重复请求、删除/编辑冲突、账号隔离、迁移中断及远程备份恢复演练。
