# 本地模式数据设计

## 数据来源与隔离

资产仓储根据持久化的 `StorageMode` 选择数据源：

- `LOCAL`：Room 本地数据库是唯一事实来源，不要求网络或服务器地址。
- `REMOTE`：当前选中的 HTTP JSON 服务是唯一事实来源，继续保留明确的网络错误和重试。

本地数据库与远程地址按数据源隔离。切换模式不删除、上传、复制或合并任何记录，也不把远程连接失败自动降级为本地模式。本地模式的用品数据保存在同一设备的独立本地库；远程模式使用 M5 的服务器用品记录和按服务器/账号隔离的本地缓存，切换模式不会自动迁移。

切换模式时，界面先取消旧模式的加载和变更请求，再清空旧模式的列表/详情状态；请求开始时捕获模式快照，旧响应不得写入新模式状态。正在编辑的表单由 UI 在切换前要求保存或放弃。

## Room 迁移规则

Room 数据库使用显式 schema 版本和逐版迁移，禁止 destructive migration。资产表保留稳定的跨数据库字符串 ID、状态、归档时间和派生计算所需的原始字段；派生的持有天数和日均成本不作为事实存储。新增字段只追加 nullable/default 列，旧记录可正常读取。

本地备份恢复在 Room 单事务中执行，失败回滚全部写入。应用升级时先执行 Room migration，再允许业务读取数据库。

## 备份格式 v1

Room 当前为 v2：从 v1 升级时先补齐资产资料字段和时间字段，再创建 `expiry_items` 表，旧资产数据保留并使用空值/空数组/纪元时间默认值。迁移显式注册，不启用破坏性迁移。

本地完整备份是 JSON 文件，顶层包含 `format`、`version`、`exportedAt`、`assets` 和 `expiryItems`。金额使用整数 cents，日期使用 `YYYY-MM-DD`，时间戳使用 RFC 3339；资产保留 ID、状态、退役日期、归档时间、图标和全部资料字段。备份不包含服务器凭据；恢复目标固定为本地库，不改变当前模式或远程地址。

导入前校验版本、必填字段、枚举、日期和关联关系，并展示覆盖范围与记录数。只接受已知版本；未知未来版本拒绝导入。恢复前自动生成当前本地数据备份。恢复失败时原库保持不变。

M2/M3 字段采用可选字段和默认值向后兼容 v1；导出时写入当前版本，导入旧版本时填充默认值。后续格式变更必须新增版本解析器和测试，不修改已发布格式的语义。
