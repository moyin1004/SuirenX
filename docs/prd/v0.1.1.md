## 目标

v0.1.1 提供共享 Android 同步账号数据的 Web 客户端，以及由超管管理账号、全部业务数据、通用文本配置文件和受限 API token 的管理区。Android 客户端同时发布 `0.1.1` 版本，识别并提示服务器关闭注册的稳定错误。配置管理不绑定特定格式或产品；Mihomo 是首个使用场景，也可用于 Nginx 等配置。Android 到期提醒不属于本版本，继续按 [到期提醒规格](reminders-spec.md) 延后规划。

## Web：共享数据的资产与用品管理

- 提供响应式 Web 客户端，覆盖 Android 核心业务体验：总览、资产列表/详情/新建/编辑、持有天数与日均成本、退役/重新启用、归档/恢复/显式删除；用品列表/新建/编辑、期限状态、用完/丢弃/归档/恢复/显式删除，以及搜索、排序/筛选。遵守现有金额、日期、归档及用品期限规则。
- 归档与资产生命周期状态相互独立。归档资产默认列表和总览中隐藏，但仍可通过归档列表和详情读取；归档记录必须先恢复，再单独编辑。显式删除始终单独提交并保留同步 tombstone。
- Web 总览提供与 Android 同口径的用品待处理入口；不要求复刻 Android 系统通知、Room 备份/恢复或本地同步设置等平台专属能力。
- 用户使用现有 SuirenX 账号登录，只能读写自己的数据。Web 操作复用服务器的版本号、增量同步事件、tombstone、幂等和冲突边界；Android 继续以 Room 为唯一本地事实来源，Web 写入必须可由 Android 后续同步发现，不能直接修改 Android 本地数据。
- Web 页面不要求用户配置服务器地址或连接参数。浏览器只请求同源 Web 后端，由 Web 后端代理数据访问并执行鉴权；服务器地址、凭据和下游服务细节不暴露给浏览器。
- Android 与 Web 同时修改同一记录产生冲突时，Web 用户查看冲突双方并手动选择处理方式，遵循现有同步冲突规则；不自动覆盖或字段合并。
- Web 专用业务接口与 Android 同步接口分开命名和授权；共用领域服务、仓储和同一数据，不向 Android 同步接口添加通用 CRUD。
- 保持 API 的 HTTP + JSON、snake_case 与日期/金额约定。新增接口先更新 `api/proto`，再通过仓库固定 Hertz 生成器生成路由与模型。
- Web 创建/更新/删除通过 `Idempotency-Key` 和记录 `base_version` 提交；版本冲突返回服务器版本及远端快照，由用户选择保留哪一方后再次提交。

## Web：超管和账号管理

- 普通账号只使用现有凭据访问、同步自己的资产/用品，不管理配置文件或 API token。配置的超管账号可进入管理区，管理所有账号及其资产/用品，并保留普通业务访问能力。
- 超管用户名和初始密码通过服务端 secret/environment 注入，不写入仓库、前端包或数据库明文；启动时仅在账号不存在时创建并校验角色，已存在账号的密码不因普通重启而静默重置。配置缺失、撞名或无效时拒绝开放管理登录并给出可操作的服务端错误；密码轮换需走显式运维流程。
- 管理区支持查看账号、查看账号状态、停用/恢复账号；停用账号后阻止后续登录。已签发的无状态 JWT 不即时撤销，在自然过期前仍按现有认证规则有效；本版本不实现 JWT 撤销或停用状态的逐请求检查。不得提供无审计的密码明文读取或身份冒用入口。
- 超管可管理所有配置文件和 API token，并管理所有账号及其资产/用品数据。超管管理操作记录操作者、目标、动作与时间，数据库仅保留最近 100 条审计记录；API 不返回密码散列或 token 散列。

## Web 独有：配置文件管理与 API token

- 超管可创建、读取、编辑、重命名和删除 UTF-8 文本配置文件。文件内容保存在服务端数据库；系统不解析或校验配置格式，也不保留历史版本或提供回滚。编辑器保存时以提交的完整内容覆盖当前内容；并发编辑采用最后一次保存生效。
- 文件使用稳定且永不复用的 opaque key；重命名只更改显示名称，不改变 key。配置文件管理列表展示每个文件的读取 URL path（`/api/v1/configs/{config_key}/content`），不展示服务器域名。该 GET API 返回对应文件的完整最新版原文，不做格式转换，使用明确的 UTF-8 文本内容类型。单个文件大小上限暂定为 10 MB，通过服务端全局配置修改；不支持二进制附件、脚本执行或任意目录访问。
- 超管可在服务器设置中启用或关闭新账号注册。默认启用以兼容现有部署；关闭后，服务端拒绝所有新注册请求并返回稳定错误，既有账号仍可登录。该运行时开关保存在已有的 `server_settings` 表；缺少该键视为默认启用，不新增数据库结构迁移。此设置仅阻止创建新账号，不影响账号状态管理和数据访问规则。
- API token 由超管创建和管理，每个 Mihomo 实例单独签发一个 token；每个 token 显式授权一个或多个配置 key。该模型为通用配置读取 API：其他客户端也应使用独立 token，并显式授权配置列表。超管签发时可配置 token 有效期，并可查看 token 的状态、授权范围、创建/到期时间及最后使用时间，或撤销 token。超管可通过 `PUT /api/v1/admin/config-tokens/{token_id}` 一次修改未撤销 token 的名称和授权配置集合；两者在同一事务中更新并写入审计记录，token 密钥、传递方式和有效期保持不变。授权集合至少包含一个当前存在的配置。撤销后的 token 不可编辑或恢复。
- token 密钥只在签发时展示一次；数据库只存安全散列。签发时选择该 token 的凭据传递方式：`Authorization: Bearer <token>` 或 `GET /api/v1/configs/{config_key}/content?token=<token>`；同一 token 只接受所选方式，切换方式需重新签发。请求需 HTTPS、具备速率限制、可撤销、可过期，并仅能读取明确授权的配置；不得复用 Android 登录 JWT，也不得获得账号管理或配置写入权限。
- 重命名配置不改变已有 token 的授权。删除配置不撤销 token；对已删除 key 的读取返回稳定的资源不存在错误，key 不得分配给新文件。缺失、过期、撤销或范围不足也分别返回稳定错误。Query 模式须对访问日志、反向代理日志及错误追踪中的 `token` 参数做脱敏，并返回 `Cache-Control: no-store`；任何模式均不得在响应中回显 token。
- v0.1.1 不启用数据库静态加密。不在日志中记录密码、token 或完整配置正文；审计记录只保留最近 100 条。部署时检查反向代理对 query token 的日志脱敏；若部署了 WAF/APM，也检查其日志。无法确认脱敏时使用 Bearer 方式。

## 服务端与迁移边界

- Go/Hertz 模块化单体继续使用 transport → service → repository。Web 管理 API、配置 API 与 API token API 复用服务边界，但按认证主体和权限分开授权。
- 服务器 SQLite 保持 `001_init.sql` 不变；v0.1.0 已正式发布，本版本结构变更使用不可变的编号迁移并提供升级与回滚测试。不使用 AutoMigrate，不绕过现有数据库校验。
- Web 更新资产/用品时，业务行、版本递增、同步事件或 tombstone 必须在一个数据库事务内提交。重复写入使用幂等键；Android 新版本冲突规则仍由现有同步协议处理。
- 新增 Web 前端技术栈需先盘点仓库当前工具链并写入 ADR/实现记录；前后端同源部署优先，若拆分则需明确 HTTPS、CORS、CSRF、会话策略和构建/发布责任。

## 明确不做

- 不增加库存、消耗或补货预测，不扩展提醒到已处理/已归档项目。
- 不让 Web 成为 Android 本地数据源，不移除离线优先或改变同步批次、冲突和 tombstone 语义。
- 不允许普通账号管理配置文件或 API token；API token 仅用于受限的配置内容读取，不用于资产 CRUD、配置写入或账号管理。
- 不上传或执行配置文件，不导入二进制文件，不新增多租户组织、角色编辑器或任意权限脚本。
- 不将签名、分发或实体设备后台验收描述为由代码实现自动完成。

## 主要风险

- Web 与 Android 同时编辑会暴露现有同步冲突边界；所有 Web 写入必须生成版本事件，不能直接绕过同步服务。
- 配置文件可能包含秘密；数据库暂不做应用层静态加密，部署方须保护数据库与备份文件的访问权限，并避免浏览器缓存或日志泄漏正文。
- 新增后台与数据库功能扩大服务端运维和备份责任；发布前需说明配置文件和 token 的数据库备份、恢复、撤销及密钥轮换流程。配置不保留版本历史，误覆盖或删除后不能在产品内回滚。
- Android 到期提醒不在本版本范围；首个接入客户端（Mihomo）读取完整配置的兼容性需按实际客户端和认证方式验收。
