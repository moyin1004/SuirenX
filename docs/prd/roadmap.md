# 版本规划

## v0.1.4：多语言支持

2026-10-20：维护者确认按本方案实施。Android、iOS/iPadOS 与 Web 已接入独立的原生中英文资源、语言入口、错误映射与数量/日期/人民币格式化；共享产品版本为 `0.1.4`。2026-10-21 已完成正式签名发布、实体 Android 保留数据升级及配套服务端部署，见 [发布记录](../history/roadmap-execution.md#v014-正式发布与配套部署)。执行证据及验收边界见 [实施记录](../history/roadmap-execution.md#2026-10-20v014-多语言支持) 与 [当前待办](../TODO.md)。以下为本版采用的产品规则。

### 首版范围与语言选择

- Android、iPhone/iPad 和 Web 同步支持简体中文（`zh-Hans`）与英文（`en`），默认跟随系统/浏览器的语言偏好列表；优先匹配受支持语言，全部不匹配时回退简体中文，延续现有中文产品行为。保留语言、文字体系和地区信息，不用简单的 `startsWith("zh")` 把繁体当作已支持语种。
- 语言列表使用自称「简体中文」「English」，不使用国旗。跟随模式显示实际生效语言，显式选择后不因系统语言改变而覆盖；恢复跟随模式后重新匹配。
- 设置中增加「语言」入口。Android 13+ 接入系统应用语言，旧系统使用独立的本地偏好与 Activity 正常重建；iOS/iPadOS 通过系统的 App 首选语言管理，应用内展示当前语言并提供设置入口，遵循系统的返回/重启生效行为。Web 提供「跟随浏览器 / 简体中文 / English」，仅在当前浏览器保存显式偏好，登录页、工作区和表单内均可使用。
- 语言是设备上的显示偏好，不属于账号/服务器，不加入业务同步或 JSON v1 数据备份。退出账号、切换服务器不改变语言，切换语言不触发上传、迁移、重新登录或清理数据。
- 切换前保存导航、搜索筛选与未提交表单草稿；不能安全保留的场景先提供明确的保存/放弃流程。不得在切换、Activity 重建或从系统设置返回时静默丢失草稿。

### 三端资源与错误提示

实施覆盖页面标题、表单、空态、加载/失败/重试、确认弹层、无障碍标签、图标名称、备份/同步提示，以及已有系统权限说明。Android 的跨模块展示资源集中在 `core/ui`，资产模块既有资源继续按模块维护；iOS 使用 App 原生目录文件，核心模块仅提供错误标识和展示值；Web 的字典与运行时随 Go 二进制离线嵌入。

| 平台 | 本版实现 |
| --- | --- |
| Android | 使用 `strings.xml` / `plurals`、`stringResource` / `pluralStringResource`；保留完整中文默认资源，增加英文资源并声明受支持语言。继续使用 `ComponentActivity`，Android 13+ 使用 `LocaleManager`，旧系统通过本地偏好和带语言配置的 Context 重建，无新增 AppCompat 依赖。 |
| iOS / iPadOS | 使用 String Catalog（`.xcstrings`），覆盖 SwiftUI、动态文本、复数和必要的 `InfoPlist` 文案；核心模块保持独立于 SwiftUI/UIKit，错误通过结构化类型交由展示层本地化。 |
| Web | 保留 Go 嵌入的原生 HTML/CSS/JavaScript，增加本地打包的语言字典与轻量 `t(key, args)`、复数和格式化工具；跟随 `navigator.languages`，更新页面 `lang`、标题与可访问名称。首屏按已保存偏好/浏览器偏好选择语言，避免先中文后英文闪烁。 |
| 服务端与数据层 | 保留现有稳定错误码、HTTP 状态与参数，客户端按错误码生成本地化消息；不让业务逻辑比较翻译后的字符串。未知错误给出当前语言的通用提示并保留诊断码，不把原始服务端文本或异常栈直接显示给用户。无需为界面语言新增服务端翻译接口。 |

三端共享术语和逻辑键语义，不引入跨端运行时翻译框架或资源代码生成流水线。使用业务语义键，例如 `asset.archive.confirm`（Android 可用 `asset_archive_confirm`）；完整句子通过占位参数表达，不拼接「数字 + 天」或中文片段。不同上下文不因中文相同而强行复用同一个键。

首批术语：资产 `Assets`、服役中 `Active`、已退役 `Retired`、已归档 `Archived`、恢复归档 `Unarchive`、日均成本 `Cost per day`；备份恢复使用 `Restore backup`，避免与恢复归档混淆。英文需按实际上下文校对，不能仅靠逐字翻译。

### 语言、格式与业务数据分开

- 多语言不等于多币种。当前金额仍是人民币 CNY，保持整数分和原有计算/舍入规则；英文显示也必须明确是 CNY，不随语言改成 USD，不做汇率换算。金额、小数和分组使用本地化格式工具，输入解析与校验须配套，最多两位小数；零元、留空和卖出价的语义保持不变。
- 日期仅在展示时本地化。存储、备份和 HTTP 继续使用 `YYYY-MM-DD` / RFC 3339，日期输入仍按现有公历日期规则；切换语言不改变时区、购买日、退役日、到期日或持有天数。不得将 date-only 值按 UTC 时间戳转换后显示为前一天。
- 资产名称、备注、标签、位置、服务器名称和配置正文等用户内容保持原文；协议字段名、状态枚举、`icon_key`、ID、备份结构不翻译。排序可以使用显示语言的排序器，但不改写数据或改变既有排序字段/方向。
- 复数由平台资源或复数规则处理，覆盖 `0 / 1 / 多个`；例如 `1 day` 与 `2 days`，不用英文 `day(s)` 规避语法。

### 实施顺序与验收

1. 盘点三端可见文案、错误来源和格式化入口，固定术语、键与语言回退规则；补充语言匹配、参数/复数及 CNY 格式的针对性检查。
2. 先更新并预览现有唯一 OpenDesign 原稿：语言入口、中文/英文主要页面、空态/错误/确认弹层、长文本和 iPad 窄窗口；若原稿访问受阻，记录差异并保留依赖 UI 待办，可继续资源/错误模型等无关准备。
3. 先完成完整默认资源与结构化错误，再按设置、资产、用品、同步/备份、Web 管理功能逐块接入英文；每块同时核对两种语言，不将半翻译版本标为完成。
4. 验证显式选择、跟随系统、偏好列表匹配、未知语言回退、切换后重启和草稿恢复；覆盖 Android 低版本/13+ 与 iPhone/iPad 系统语言路径、Web 刷新。
5. 检查翻译键完整性、占位参数类型/数量、复数、无障碍文本与新增硬编码文案；可使用伪本地化暴露长文本，但不在用户语言列表显示未完成语种。
6. 验收英文长文案、Android 窄屏、大字号、iPad 旋转/分屏、Web 390 px 和桌面；关键金额与日期不溢出。验证切换前后本地数据、备份及跨端同步的业务值一致，不依赖中文文本作为自动化定位标识。

辅助字号遵循原稿的补充规则：内容宽度不超出视口，资产卡片可切为单列，统计与工具栏在必要时换行；底部导航在辅助字号下可仅显示图标，但保留完整可访问名称。iPad 侧栏随字号扩宽以容纳完整词语，标准字号几何保持原样。金额与持有天数不得只在语义树完整、实际画面却被裁切；窄卡片使用简洁文案及受限字号适配。

首版不扩展繁体、日语、RTL、多币种、机器翻译用户内容或在线语言包；后续按实际需求增加资源与验收。v0.1.3 未完成的真机/后台可靠性补验继续保留，不因创建新版本而关闭。

实现依据：[Android 应用语言](https://developer.android.com/guide/topics/resources/app-languages)、[Apple String Catalog](https://developer.apple.com/documentation/xcode/localizing-and-varying-text-with-a-string-catalog)、[Web Intl.NumberFormat](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat)。

2026-10-12：维护者确定本版本主要修复实际使用中遇到的 bug 和体验问题。Android 与 Web 的具体问题按反馈逐项记录，实施优先级由复现结果、数据影响和使用阻碍决定。

- 每项反馈记录平台、操作步骤、实际结果和期望行为；先复现和定位，再修复并验收原操作路径。
- UI 或交互调整先更新既有 OpenDesign 原稿，再实现应用；验收包含实际预览或浏览器/设备交互证据。
- 首批 Android 反馈：资产页默认「服役中」，完整/压缩总览随状态、标签和搜索筛选；切页时标签与正文同步并保留页面状态；用品期限日期框与其它字段同宽；退役日期通过日历选择，限定购买日至今天，取消不提交。首页继续汇总全部未归档资产。
- 资产页总览卡片布局：顶部「资产概览」后紧跟「当前标签下数量/总数」（如 `3/5`），取消最右侧筛选徽标；分子随状态、业务标签及搜索变化，分母为包括已归档在内的全部资产数。金额区左侧「总资产金额」、右侧「日均成本」，总资产字号略大；下方浅灰圆角指标条分别为「服役中」「已退役」「最长持有天」，每组文字与数值并排。继续使用当前筛选口径。
- 2026-10-13 追加反馈：「全部」筛选包含已归档资产，归档记录参与此筛选的购入总额、项数与最长持有天汇总；服役中/已退役筛选及日均成本仍排除归档记录，首页仍统计全部未归档资产。归档记录保持只读、恢复后才能编辑。
- 2026-10-13 实体手机反馈：资产页总览金额保持单行，宽度不足时适配字号；资产卡片名称保持单行，超出可用宽度时自动横向滚动，短名称静止，卡片点击仍进入详情查看完整名称。
- 名称使用无额外字距的排版，以实际文字宽度判断是否溢出；能完整放入卡片的中英文混合名称保持静止。
- Android 账号页的密码显示切换使用输入框右侧眼睛图标按钮，移除独立的文字按钮；图标提供「显示密码 / 隐藏密码」可访问说明，提交中保持禁用。
- 注册密码的实际规则：8–72 个可打印 ASCII 字符（英文大小写字母、数字、英文符号、空格），不允许中文、emoji、控制字符；不要求必须混合大小写、数字或符号，空格不自动裁剪。密码框下展示这些要求，删除 UTF-8 字节说明。已有账号登录仍按原密码核验，不因新注册规则失效。
- 既有 Web 表单提交修复及未发布的认证限流、配置上限、审计日志改动保留进度。待办和未验证范围见 [当前待办](../TODO.md)，具体问题列表随维护者反馈补充。
