## 服务端：剩余原稿与安全加固

服务端与内嵌 Web 客户端已随 v0.1.2 发布，并于 2026-10-15 部署：登录/注册在服务层按被请求账号名与连接对端地址限流，超限返回 `429 too_many_attempts`；未知账号登录与错误密码一样执行一次 bcrypt 比较；配置正文上限收敛为 10 MiB（`domain.MaxConfigContentBytes`），HTTP 请求体上限由六倍正文上限加 2 MiB 推导，当前为 62 MiB，以支持最坏 JSON 转义；Web 管理页与部署文档明确"停用账号不撤销已签发 JWT"。生产反向代理已同步为 62 MiB；失败登录限流、管理员登录、重启前 JWT、审计权限、配置上限读取和线上 JS/CSS 哈希均已核对，保留现有配置大小设置，未强制改为总上限。

限流已统一为 `internal/ratelimit` 的键控令牌桶（`golang.org/x/time/rate`，键 map 自管）：认证的账号/对端预算与配置内容读取的 token/对端预算共用同一实现，原来的固定窗口与 `ConfigService` 内的滑动窗口实现均已删除。所有额度在比对或查库之前扣减，失败尝试与成功请求等价计费；配置读取因此必须保留"对端地址"维度，否则调用方只要更换猜测的 token 值就能拿到新额度。新增直接依赖 `golang.org/x/time v0.15.0`（`v0.16.0` 要求 Go 1.26，不可用），`go.mod` 的 `go` 指令因此由 `1.25` 规范为 `1.25.0`。
